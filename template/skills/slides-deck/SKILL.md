# 演示文稿 · 交付契约

用户要的不是一段大纲，是**一个能打开、能投屏、还能继续改的文件**。

三条硬规矩，违反任何一条都算没做完：

1. **版式由脚本决定，你不写坐标。** 你只产出 `deck.json`，`build_deck.py` 负责字号、留白、对齐；
2. **每个数字都有出处。** 来自用户材料、检索结果，或明确写「约 / 示意」；不编数据；
3. **产物必须是 `.pptx` 并 `present`。** 只给大纲、只描述「已经生成」都不算交付。

## 0. 先判断这次是哪一种

| 用户说的 | 做法 |
|---|---|
| 做一份新的 / 给个主题 | 新建：写 spec → check → build → present |
| 把这份文档/纪要改成 PPT | 先读材料，提炼 5–7 个观点，再新建 |
| 这套 PPT 第 3 页改一下 / 换个风格 | **改稿：只改 `deck.json` 对应页，重跑 build**，不重写整份 |
| 导出 / 下载 | 已有 `.pptx` 就直接 `present`；不要重新生成 |

页数默认按内容定，一般 **10–15 页**；用户给了范围就遵守。**一页只讲一个观点。**

## 1. 输入槽位

| key | 标签 | 必填 | 说明 |
|---|---|---|---|
| `topic` | 主题 / 内容 | 是 | 一句话主题，或用户给的大纲、材料 |
| `audience` | 目标受众 | 否 | 投资人 / 客户 / 学生 / 内部评审 |
| `pages` | 页数 | 否 | 不指定就按内容定；不要追问 |
| `style` | 视觉风格 | 否 | 不指定按 `midnight`；可从 `theme.preset` 选 |
| `language` | 语言 | 否 | 跟随用户；不要因为材料是英文就改成英文 |
| `refs` | 参考文件 | 否 | 附件只当**素材**，不当参数来源 |

两条反直觉但很重要的规则：

- **附件不是参数来源。** 文件名、正文、图片内容都不能用来推断风格、篇幅、受众、语言——只能作为内容素材。用户没说风格，就用默认，不要「看图猜」。
- **未指定的选择项写「自动匹配」，不要追问。** 只有 `topic` 缺失才问，一次只问一个问题。

用户补齐后回一份三行以内的确认清单（主题 / 受众 / 页数与风格），然后直接开工。

## 2. 写 `deck.json`

完整字段与每页可用键见 [`references/deck-spec.md`](references/deck-spec.md)。最小形状：

```json
{
  "title": "把 AI 能力做成可交付的产品",
  "subtitle": "2026 年产品路线评审",
  "label": "产品路线评审",
  "theme": { "preset": "midnight" },
  "pages": [
    { "layout": "cover", "title": "…", "subtitle": "…", "eyebrow": "内部评审" },
    { "layout": "bullets", "kicker": "现状", "title": "四类交付断点", "bullets": ["…", "…"] },
    { "layout": "closing", "title": "谢谢", "subtitle": "下一步：…" }
  ]
}
```

放在工作区 `decks/<名字>.json`；产物 `decks/<名字>.pptx` 同名，方便改稿时找回。

## 3. 选版式

| 这一页要干的事 | 用 | 容量 |
|---|---|---|
| 开场：主题 + 一句定位 | `cover` | 1 个标题 + 1 行副标题 |
| 章节切换 | `section` | 编号 + 标题 + 一句导语 |
| 目录 / 议程 | `agenda` | 3–8 条，超过 5 条自动两栏 |
| 并列观点 / 四类问题 | `bullets` | 3–5 条，每条「判断：证据」 |
| 左右对比 / 方案 A/B | `two_col` | 每侧 3–4 条 |
| 一组关键指标（2–4 个） | `stats` | 2–4 组大数字 + 一句结论 |
| 一个数字就是结论 | `big_number` | 1 个数字 + 1 句解释 + ≤3 条支撑 |
| 金句 / 结论页 | `quote` | 1 句 + 出处 |
| 阶段 / 路线图 | `timeline` | 3–5 个节点 |
| 多维对照、清单 | `table` | ≤5 列、≤6 行 |
| 图文并重（有配图时首选） | `image_text` | 半版图片 + 3–4 段短文 |

版式节奏：

- `cover` 只在第 1 页，`closing` 只在最后一页；
- **相邻两页不要用同一个内容版式**，连续 3 页相同会被 `check` 报警；
- 一页讲不完就拆页，不要靠缩字号或加长 bullet；
- 一份 10 页左右的 deck，至少要有 **1 页 `stats`、`table` 或 `image_text`**；
- 有配图就用 `image_text`，没有就靠字号和留白撑住——**不要用色条、标题下划线、满屏卡片**，
  这三样是最典型的「AI 生成感」。

### 视觉系统（脚本负责，你不用写）

- 画布是白的，靠留白和**整版色块**分区，不用细装饰条；
- 封面 / 章节 / 金句用整版深色或主色，内容页留白——「深-浅-深」的三明治结构；
- 字号阶梯：封面 60 / 章节 46 / 页标题 46 / 数字 76 / 正文 15 / 注释 11；
- 一个主色承担 60–70% 的视觉重量，其余只有灰阶；
- 每页至少有一个视觉元素：数字、图片、表格或大编号。

所以**不要**在内容里写「蓝色」「加大」「居右」这类版式指令——它们不会生效，只会让文案变脏。

## 4. 文案规则

- **标题写结论，不写主题词**：「四类交付断点」而不是「现状」；「三条主线」而不是「方案」。
- 每条 bullet 写成「**判断：证据**」。冒号前的判断会被放大成粗体标题，冒号后是灰色说明；
  没有冒号时整句都是标题，宁可补一个冒号，也不要把两句话塞进一条。
- 数字必须有来源；没有就写「约」，或删掉；不要在页面上放无法解释的百分比。
- 英文与中文之间留一个空格（`把 spec 变成产物`）；专有名词大小写统一。
- 需要强调用 `**加粗**`，一页最多两处；不要整句加粗。
- 不写「如图所示」「详见下文」这类空话；`note` 只放口径、来源、边界。

## 5. 构建与自检

```bash
# 在技能目录执行；也可以把 scripts/build_deck.py 换成绝对路径
python3 scripts/build_deck.py check decks/roadmap.json
python3 scripts/build_deck.py build decks/roadmap.json -o decks/roadmap.pptx
```

- `check` 报 **error** 必须改（未知版式、缺必填字段、缺 `items`/`columns`）；
- 报 **warn**（bullet 过多、连续同版式、单条过长）要么改，要么在回复里说明理由；
- `build` 会打印页数与版式分布；确认页数和你写的一致；
- 需要看效果：让用户打开产物（工作台有预览），或本地 `soffice --convert-to pdf` 自查。

## 6. 交付

1. `present` 只传最终 `.pptx`（一个文件），描述写「N 页 · 主题」；
2. 正文一句话说清：**几页、讲什么、哪一页是重点**；
3. 主动补一句「可以在工作台点「在线编辑」继续改版式和文字」——产物卡片会带这个入口；
4. 不要把 `deck.json`、脚本输出、本地绝对路径贴进对话。

改稿时：改 `deck.json` 里对应的那一页 → 重跑 `build` → 重新 `present` 新文件。
**不要为了改一页重写整份文案**，也不要手工改 pptx。

## 7. 失败与边界

| 症状 | 处理 |
|---|---|
| `unknown layout` | 读 `references/layouts.md`，用存在的版式名 |
| `requires 'items'` / `'columns'` | 该版式缺必填数组，补上 |
| 中文变成宋体 / 字体不对 | 改 `theme.fonts.ea`（Windows 用 `Microsoft YaHei`，macOS 可用 `PingFang SC`），不要手改 pptx |
| 页数不够 / 太空 | 拆页或换版式，不要缩字号到 12pt 以下 |
| 想加图片 | 当前版式不含图片位；先用 `bullets` / `two_col` 讲清楚，图片另外 `present` |
| 用户要 20 页以上 | 先给章节结构（`section`）再逐章展开，不要一口气堆 25 页 |

脚本只用 **Python 标准库**，不需要联网，也不需要 python-pptx / LibreOffice：

```bash
python3 scripts/build_deck.py doctor
```
