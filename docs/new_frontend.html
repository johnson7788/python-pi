读一下 web/src/lib/useAgent.ts，找出 reconnect 里可能重复建连的地方，改掉，再补一个回归测试。

思考过程
先看 socket 的生命周期：effect 的依赖数组里带了 connect，而它每次渲染都是新函数，state 一变就重跑 effect、再建一条连接。另外 catch 分支里的重连定时器没有存 ref，close 回来时旧 timer 还会再开一个 WebSocket。两处都要收敛到一个 ref，并在 close 时清掉 pending timer。

找到了两处会导致重复连接的写法，都在 useAgent.ts 里：

  1. effect 依赖了每次渲染都新建的 connect —— 每来一次 state 更新就重跑一遍，socket 被反复重建。
  2. 重连定时器没有落 ref —— close 事件回来时，上一轮排的 timer 仍然会触发一次 new WebSocket。
web/src/lib/useAgent.ts 
// 连接只跟 sessionFile 有关；重连定时器收进 ref，close 时清账
const timerRef = useRef<number | null>(null)

useEffect(() => {
  const socket = new WebSocket(url)
  const onClose = () => {
    if (timerRef.current !== null) return   // 已经有排队的重连
    timerRef.current = window.setTimeout(connect, backoff(attempt++))
  }
  socket.addEventListener('close', onClose)
  return () => {
    socket.removeEventListener('close', onClose)
    if (timerRef.current !== null) clearTimeout(timerRef.current)
    timerRef.current = null
    socket.close()
  }
}, [sessionFile])   // ← connect 不再进依赖
