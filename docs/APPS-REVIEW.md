# 「应用」功能：现状、已改与仍缺

> 2026-11-10。产品决定：**应用是部署级配置，只有管理员能改，所有成员看到同一套。**
> 本文同时是改动记录和剩余清单。

---

## 1. 模型（已改）

| 项 | 之前 | 现在 |
|---|---|---|
| 归属 | 每个用户一份（`apps.uid`） | **部署级一份**（`team_apps` / `team_app_modes` / `team_app_capsules`） |
| 权限 | 任何登录用户改自己的 | **只有管理员**能新建/修改/删除/排序/导入/导出；成员只读 |
| 审计 | `app_audit.uid` 按用户 | `team_app_audit` 记录 actor + 完整 before/after |
| 排序 | `sort` 列从不写入 | `POST /api/apps/order` 持久化顺序 |
| 分发 | 无 | `POST /api/apps/{id}/duplicate`、`GET /api/apps/export`、`POST /api/apps/import` |
| 模式字段 | 提示词 + 技能 + 胶囊 | 加 `examples` / `placeholder` / `icon`（首页示例、输入框占位、图标） |
| 校验 | 只截断名称 | 提示词 ≤4000、示例 ≤6×120、胶囊 ≤12 且必须是对象、accent 必须 `#rrggbb`、名称唯一、模式 ≤10 |

schema 版本 14；内置目录在第一次访问时灌入一次，之后**不会被重新灌入覆盖**。

**注意**：之前按用户改过的应用不会迁移过来——旧的 `apps` 表保留但不再读写。如果需要保留某位管理员的旧配置，先导出/手工抄一份，或者告诉我加一个一次性迁移。

---

## 2. 会话归属（已改）

- 会话头新增可选 `app` / `mode`（旧文件没有这两个字段，读取为 `null`）；
- `SessionInfo` 透出，`/api/sessions?app=&mode=` 按应用过滤；**旧会话（app=null）在所有应用里都可见**，避免历史消失；
- `switch_session` 时若目标会话属于另一个应用，返回错误并**拒绝装载**，避免「研究综述的历史 + 演示文稿的提示词」；
- 侧栏会话行显示应用名（非当前应用时）；
- fork 出来的会话继承源会话的 app/mode。

仍未做：**按应用统计会话/成本**（usage 表没有 app 维度）。

---

## 3. 容量（已改）

- `max_active_users` 现在按**不同用户数**计；新增 `max_workers_per_user`（默认 6，`PI_MAX_WORKERS_PER_USER`）；
- 同一用户达到 worker 上限时，回收其最久未活跃且不忙的 worker；全忙才报错；
- 错误文案区分「用户已满」和「你自己的会话已满」。

仍未做：切换应用时立刻回收同用户其他 worker（现在靠空闲超时 30 分钟 + 上限回收）。

---

## 4. 删除清理（已改）

- 删除前检查定时任务：仍被引用则 409，并列出任务名；
- 删除时清理 `plugin_enable` 与 `composition_session_pointers`；
- 审计记录保留；
- 应用更新/删除/恢复会驱逐**所有用户**该应用的 worker（`registry.evict_app`），不再只驱逐操作者自己的。

---

## 5. 编辑体验（已改）

- 技能绑定从「逗号分隔文本」改成**多选**，数据源 `/api/skills`；不存在的技能标红提示，绑定为空时明确写「本模式不加载技能」；
- 自定义模式不再落到「办公」的示例/占位符：每个模式自带 `examples` / `placeholder` / `icon`；
- 编辑器加「预览」：返回每个模式最终追加的提示词与字符数；
- 首页示例、输入框占位、模式图标都按模式读；
- 保存前显示提示词字符数，超 4000 变红。

---

## 6. 仍在 P2（没做）

| 项 | 为什么可以等 |
|---|---|
| 应用级模型 / 思考强度 / 工具集 | 需要改 worker 组合与 `BootstrapOptions`，影响面比本轮大；建议单独一轮 |
| 按应用的使用统计 | 需要给 usage 表加 app 维度 + 聚合查询 |
| 应用市场 / 索引 | 导出/导入 JSON 已能跨部署搬；市场是下一步 |
| 团队 → 多团队（多租户） | 当前一个部署一套应用；多团队要再加 tenant 维度 |
| 旧 per-user 应用迁移 | 见 §1 的说明 |
| 容量回收策略优化 | 现在「上限回收」够用，主动回收是体验优化 |

---

## 7. 测试

`tests/test_apps.py` 现在覆盖（12 个）：

- 目录字段、组合、未知 app 回退；
- 团队共享 + 只灌一次 + 重开数据库仍生效；
- 管理员/非管理员权限；
- CRUD、内置删除保护、恢复默认；
- 复制、排序、导出、导入；
- 删除被定时任务阻挡、删除后清理插件启用；
- 会话头 app/mode roundtrip；
- 跨应用 `switch_session` 被拒绝。

仍缺：容量上限的并发测试（需要 stub 掉 bootstrap）、计划任务删除后不再降级运行、技能白名单为空的运行时行为。
