## 采用的模式

每个 router 模块暴露：

```python
def register(app: FastAPI, *, <它真正需要的依赖>) -> None:
    @app.get("/api/...")
    async def handler(...): ...
```

依赖通过关键字参数显式传入（而不是闭包捕获 `create_app` 的局部变量），所以：

- 模块可单独 import、可单独测试；
- 新增依赖会体现在函数签名上，而不是"突然能访问到某个变量"；
- `app.py` 末尾的调用点就是依赖清单。

共享 helper（`require_team_mode`、`ensure_default_workspace`、`workspace_for`、`resolve_workspace` …）
暂时留在 `create_app` 里，通过参数传入。等所有路由搬完，再把它们提升为独立模块的函数。

## 每搬一组的步骤（照抄即可）

1. 用 AST 定位该组路由（含紧邻的 helper def）的行区间；
2. 建 `routers/<name>.py`：模块 docstring + 显式 import + `register(app, *, ...)`；
3. 把区间文本 dedent 4 后放进 `register`，`_private_helper` 改名为模块内函数；
4. `app.py` 里把区间替换成一次 `register_<name>(app, ...)` 调用；
5. `ruff check --fix`（会自动删掉多余的 import）；
6. `pytest -q tests/test_<area>.py`，再跑全量；
7. 单独提交，提交信息写清搬了哪些路由。

## 验收标准

- `routers/` 下每个模块都能被单独 import（`python -c "import pi_server.routers.x"`）；
- `create_app` 里只剩：配置/注册表/数据库初始化、helper 定义、中间件、lifespan、`register_*` 调用；
- 全量 `pytest` 与 `ruff check .` 通过；
- `app.py` 降到 1200 行以内。当前 2134 行，再搬 workspace/schedules/plugins/market/misc 后约为 900 行。

## 风险与对策

- **路由顺序**：FastAPI 按注册顺序匹配，`/{path:path}` 的 SPA fallback 必须最后。搬完后确认它仍是最后一个注册的。
- **闭包依赖**：把"用了哪个 helper"写成参数，漏一个会在 import 时就报 `NameError`（比运行时才发现好）。
- **重复注册**：搬完后原区间必须删除，`pytest` 里"同一路径注册两次"会以最后一个生效而不报错；用 `len(app.routes)` 做一次冒烟断言更稳。
- **WS**：`connection.send` 的顺序与 `ready`/`state`/replay 的顺序强相关，搬动时只改函数位置，不改一行顺序。
